# Codex のプロジェクトコンテキストにノートを使う

長期間の開発では、プロジェクトの概要や現在の作業状態を Markdown ノートへ分けて置くと、Codex が作業を再開するときの前提を短く共有できます。このレシピは、そのために `agent_notes` と Codex のスキルを組み合わせる一例です。

これは任意の運用です。`agent-notes-mcp` は、ノートのディレクトリ構造、ファイル名、frontmatter、更新方針を強制しません。

## 例の構成

書込み可能な root を `notes-work` として設定した場合、リポジトリごとのノートを次のように置けます。

```text
projects/
  example-repository/
    overview.md
    handoff.md
    inbox/
```

- `overview.md`: プロジェクトの目的、構成、現在も有効な設計上の前提
- `handoff.md`: 現在のブランチ、未コミット変更、検証結果、次に行うこと
- `inbox/`: 別の作業やセッションから受け取る連絡（必要な場合だけ）

最初はノートを一つだけ作っても構いません。作業を続ける中で、ユーザーが必要と判断したときに `overview.md` と `handoff.md` へ整理していく方が扱いやすくなります。

## スキルにする理由

毎回の作業開始時に「現在のノートを読んでから調べてください」と依頼する代わりに、スキルへ次の判断を記述できます。

- Git リポジトリで実質的な作業を始めるときだけノートを確認する
- リポジトリ名に対応する `overview.md` と `handoff.md` を読む
- 未処理の受信箱があるときだけ、その中から関係するものを読む
- MCP やノートが利用できない場合は、通常どおり作業する
- 明示的な依頼や合意なしに private ノートを作成・更新しない

このリポジトリの[スキル例](../../examples/project-notes-context/SKILL.md)は、この運用をもう一段具体化しています。`handoff.md` の管理ブロック更新、複数ノートの安全な一括更新、activity log、ブランチ別ノート、プロジェクト間の inbox も扱います。これは実際の継続開発を想定した、意図的に意見を持つ運用例です。必要な節だけを残して使えます。root ID、パス、ノートの命名規則は自分の環境に合わせて変更してください。

## 使い始める手順

1. `agent_notes` の設定に、プロジェクトノート用の `write_roots` を追加する。例では ID を `notes-work` とする。
2. スキル例を Codex のスキルとして利用できる場所へコピーし、root ID や自分の運用に合わせて編集する。必要なら同じディレクトリの [`AGENTS.md.example`](../../examples/project-notes-context/AGENTS.md.example) を、各環境の `AGENTS.md` に取り込む。
3. あるリポジトリで、Codex に「現在のプロジェクトの概要と引継ぎノートを作り、今後の作業開始時に参照したい」と明示して最初のノートを作る。

スキルは読込みの習慣を自動化するもので、ノートを作る権限や private な内容を公開する権限を与えるものではありません。公開リポジトリには、実ノートではなくスキル、匿名化した設定例、共有可能な運用規約だけを含めてください。
